## Purpose

使管理员可以可靠地将关联配置作为一个版本发布，保护持久凭证和已有账本，并通过版本状态、失败恢复及回滚明确判断网关实际运行配置。

## ADDED Requirements

### Requirement: 凭证和版本持久化
系统 SHALL 加密持久化后端凭证，保存不可变配置版本与可编辑草稿；快照、日志和差异查询 MUST 不公开凭证值。
#### Scenario: 轮换密钥
- **WHEN** 替换已存在的后端 Key
- **THEN** 新草稿引用新密钥，旧运行版本继续可用，发布前审计脱敏包含新旧密钥

### Requirement: 原子发布与恢复
系统 SHALL 串行校验并平滑发布配置，检查运行版本和健康状态，失败恢复旧版本；重启后 SHALL 核对未完成发布，草稿更新 SHALL 检查版本冲突。
#### Scenario: 并发修改
- **WHEN** 使用过期草稿版本保存
- **THEN** 返回 409，不覆盖较新草稿
#### Scenario: 发布失败
- **WHEN** 配置检查或新版本健康确认失败
- **THEN** 恢复旧运行版本并展示失败状态，Redis 和审计数据不清空
#### Scenario: 流式请求与回滚
- **WHEN** 流式请求期间发布或回滚
- **THEN** 已开始请求使用原配置，新请求使用新版本；回滚预览包含用户及 Key 状态变化
