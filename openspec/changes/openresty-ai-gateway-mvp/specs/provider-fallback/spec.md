## Purpose

通过有边界的主备切换提高模型调用可用性，同时避免重复提交有潜在费用的生成请求。为每一次实际后端尝试建立独立记录，确保故障恢复、用量统计和预算结算可以关联并核对。

## ADDED Requirements

### Requirement: 保守有序重试
系统 SHALL 按模型配置选择主备候选，默认总尝试数为 2（含首次），MVP 可配置为 1 或 2。默认仅在能够证明未向上游发送任何请求字节、未收到上游响应、且客户端尚未收到响应时，对连接失败或连接超时切换至兼容备用后端。开启额度耗尽切换时允许本规格单独定义的受限例外。

#### Scenario: 主后端连接拒绝
- **WHEN** 主后端连接被拒绝，备用兼容且预算允许
- **THEN** 备用被调用一次并返回结果，请求最多两次尝试，每次拥有不同 attempt_id

#### Scenario: 候选耗尽
- **WHEN** 两个候选均无法连接或尝试上限为 1
- **THEN** 在有限时间内返回 502 或 504，不循环重试，并记录所有实际尝试

### Requirement: 禁止不安全重放
系统 MUST 不因普通上游 429、5xx、已发送后的读取超时或不确定发送状态自动重放 POST；客户端已收到响应头或正文后 MUST 不执行透明切换。唯一可选例外为下述经结构化错误码确认的额度耗尽拒绝，默认关闭。

#### Scenario: 上游返回限流或服务错误
- **WHEN** 上游已收到 POST 并返回 429 或 500
- **THEN** 网关返回该错误，备用后端未被调用；可获得的 usage 仍进入该次尝试记录

#### Scenario: 流式中断
- **WHEN** 已转发一个流式内容块后连接断开
- **THEN** 流结束于中断状态，不调用备用、不输出另一模型内容，缺失 usage 不记作零

### Requirement: 尝试独立且路由完整更新
系统 SHALL 为实际尝试生成独立 attempt_id，关联同一 request_id、可信身份、逻辑模型、Provider、实际模型、价格版本和开始时间；切换候选 SHALL 同时更新目标地址、Host、TLS 名称、凭证及上游模型。

审计启用时系统 SHALL 保留同一 trace_id，每次候选单独关联上游请求/回复证据，开始证据无法持久化的备用不得被调用。

#### Scenario: 不同凭证的备用
- **WHEN** 主后端未连接成功而备用使用不同地址和凭证
- **THEN** 备用只收到其对应凭证和模型名，两个尝试可在日志和账本中分别追溯

#### Scenario: 能力不匹配
- **WHEN** 请求包含工具调用但备用不声明支持该能力
- **THEN** 该候选不被调用，不以不兼容模型静默降级

### Requirement: 可选额度耗尽切换
系统 SHALL 提供 fallback.on_key_quota_exhausted，缺省及示例值均为 false。启用且 fallback 插件开启时，仅在 HTTP 402/429 的完整、有界 JSON 响应中 error.code 或 error.type 精确匹配该 Provider 配置的额度耗尽错误码、且没有生成结果、未对客户端输出时，允许切换下一兼容候选的不同 Key。默认仅识别 insufficient_quota，不以状态码或自由文本猜测耗尽。备用可配置为不同模型；仍执行独立预算/审计准入及原有最多两次限制。

#### Scenario: 默认不切换
- **WHEN** 开关关闭或缺省且 Provider 返回 insufficient_quota
- **THEN** 原错误返回客户端，备用未被调用

#### Scenario: 额度耗尽后成功
- **WHEN** 开关开启、首选明确额度耗尽、备用使用不同 Key 且准入成功
- **THEN** 客户端在同一请求中只收到备用结果，JSON 和 SSE 均可用，原失败尝试仍有独立审计/计量记录

#### Scenario: 非额度错误或不可重试
- **WHEN** 普通限流、401、5xx、畸形/超限/不完整错误、相同 Key、无兼容候选或尝试上限耗尽
- **THEN** 不因额度开关重试；可获得的原响应保持，不将缺失 usage 当作零

#### Scenario: 切换留痕
- **WHEN** 网关选择额度耗尽备用
- **THEN** 结构化日志包含 request_id、trace_id、原/新 attempt_id、Provider、模型、Key 环境变量引用和 quota_exhausted 原因，不包含密钥值、原错误消息或请求正文
