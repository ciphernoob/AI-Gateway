- [ ] 1.3 实现 RequestContext、插件依赖和阶段调度；验证可选插件单独开关、依赖缺失拒绝及强制鉴权规则。

- [x] 3.2 实现 attempt_id、尝试状态、兼容候选筛选和最多两次调用；验证尝试 ID 独立、request_id 不变及 max_attempts=1 时不切换。
- [ ] 3.3 实现“明确零发送且无上下游响应”的切换判定与请求总时限；验证连接拒绝/连接超时可切换，缺失或模糊字节证据禁止切换。

## 4. M3a — 共享 Usage Collector

对应规格：`usage-collection`，依赖 M2。先确定事件，再接两个独立账本。

- [x] 4.1 定义并实现版本化 Usage Event、可选 trace_id 关联与 schema 校验；验证精确、未知、system 零、畸形/负数/不一致/超大整数，以及缓存/推理详情不重复相加、事件不携带正文。
- [x] 4.2 实现有界 JSON 观察和用量提取；验证超出上限转 unknown 且不影响响应转发。
- [x] 4.3 实现增量 SSE 解析与按后端能力注入 include_usage；验证 LF/CRLF、多行 data、UTF-8/JSON 跨块、usage=null、重复累计 usage 和终止块。
- [ ] 4.4 实现调用状态与首实际内容时间采集；验证 role/空 delta 不计 TTFT，断流及客户端取消保留 unknown，真实 Provider 精确零仍可识别。
- [x] 4.5 实现调用前 attempt 开始记录、dispatching 标记、周期快照与 pending 索引；验证恢复领取和 dispatching 竞态不会把已发送尝试当作未发送。
- [ ] 4.6 实现 log 阶段事件复制、timer 回调、有限退避和消费状态；验证禁止网络阶段没有 cosocket 调用，timer 失败/队列满/Redis 暂断均可见。
- [x] 4.7 完成采集集成验证；核对每次已开始尝试恰有一份最终事实或明确的未知记录，Fallback 失败尝试没有被遗漏。
